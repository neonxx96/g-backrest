## 1. Миссия и суть проекта (Executive Summary)

**SignalScript** — это специализированный веб-терминал профессионального уровня (Tier-1 Crypto Order-Flow Terminal) для внутридневного скальпинга и количественного анализа фьючерсного рынка Binance (USDT-M Futures).

### Ключевая концепция:
- **Никакой автоторговли:** Терминал работает в **строго консультативном режиме** («второй пилот» / Copilot). Он агрегирует рыночные аномалии (дельта, плотности в стакане L2, кластеры, ликвидации, открытый интерес), рассчитывает математическое ожидание сделки (EV), строит конус волатильности и запрашивает объективную оценку у AI. Окончательное решение о входе и нажатие кнопки всегда за живым трейдером.
- **Честность данных (Zero Bullshit):** Никаких синтетических заглушек (`Math.random()`), никаких скрытых подтасовок или галлюцинаций AI. Если модель недоступна или нет L2-истории — интерфейс прямо сообщает об этом.
- **Экстремальная производительность UI:** Отрисовка высокочастотных потоков (стакан L2 100мс, лента сделок) вынесена на Canvas 2D и виртуализированные списки, чтобы DOM React не тормозил при сотнях принтов в секунду.

## 5. Главные ограничения и чего мы НЕ достигли (The Honest Truth)

Новому разработчику критически важно знать эти подводные камни:

### ⚠️ Ограничение 1: Отсутствие исторического стакана L2 на бирже Binance
- **Суть проблемы:** Binance REST API не предоставляет историю стакана Level 2 (`depth`).
- **Как это решено сейчас:** Стратегии плотностей стакана (`density_bounce`, `wall_breakout`) в бэктестере используют **суррогатную модель** на базе объемов свечей и теней (wicks).
- **В живом терминале:** Стакан и плотности работают на 100% честных живых данных WebSocket. Но исторический бэктест стратегий со стаканом — это приближенная аппроксимация.
- **Решение на будущее:** Запустить локальный кольцевой рекордер (`backend/app/services/recorder.py`), сохраняющий снепшоты стакана топ-5 монет в DuckDB/Parquet на 7 дней.

### ⚠️ Ограничение 2: «Быстрый бэктест» тестирует стратегию, а не единичный лимит-ордер
- **Суть проблемы:** Кнопка «Проверить этот сетап на истории» берет SL/TP в процентах из интерактивного Risk/Reward бокса и запускает общую стратегию по истории за 14 дней. Она **не** эмулирует поведение одиночного лимитного ордера, выставленного по точной цене `entry_price`.
- **Решение на будущее:** Реализовать эндпоинт `POST /api/backtest/simulate-limit-order`, который проверяет: если бы мы выставили лимитку на уровне $P$, исполнилась бы она в течение $N$ баров и дошла бы до TP раньше, чем до SL.

### ⚠️ Ограничение 3: Технический долг файлов-гигантов (>800 строк)
- В проекте есть 4 очень крупных файла:
  - `frontend/src/components/Chart.jsx` (~3833 строки)
  - `frontend/src/components/docking/BacktestPanel.jsx` (~1950 строк)
  - `backend/app/services/orderflow_backtester.py` (~1421 строка)
  - `frontend/src/components/OrderBookDOM.jsx` (~1234 строки)
- **Почему не дробили сразу:** Приоритетом была стабильность терминала к реальной торговой сессии. Дробление без тестов несло риск регрессий. Теперь защитная сеть готова, и дробление нужно проводить строго по плану `docs/MODULARIZATION_PLAN.md`.

### ⚠️ Ограничение 4: Отсутствие файлов для Задачи 3
- В бэклоге стояла Задача 3 (перенос индикаторов из `docs/orderflow.py` и `docs/SIGNALSCRIPT_INDICATORS_SPEC.md`). Эти файлы отсутствуют в репозитории (лежат у пользователя локально). Их нужно запросить перед реализацией.

## 6. Как мы думали: ключевые инженерные принципы (Invariants)

1. **Zero Look-Ahead Bias:** Ни один индикатор или шаг бэктестера не имеет права заглядывать в бар $t+1$. Вся аналитика считается строго по закрытым барам или тикам в момент $t$.
2. **Trader-in-the-Loop (Только консультации):** Никаких прямых вызовов API размещения ордеров. Терминал готовит контекст, показывает вероятность, логирует решение трейдера, но не торгует сам.
3. **Dual-Source Data Resiliency:** Если локальный бэкенд перегружен или перезапускается, график мгновенно переключается на прямой запрос к Binance REST API без белого экрана.
4. **Canvas 2D для потока данных:** Не рендерить строки стакана и тики в DOM через `<div>` или `<tr>`. Только Canvas 2D с direct coordinate mapping и requestAnimationFrame.
5. **Quality Gate перед коммитом:** Ни один коммит не должен попадать в репозиторий без зеленого прогона `scripts/check.ps1`.
