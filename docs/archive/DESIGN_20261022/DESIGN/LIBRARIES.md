# slab_terminal: разрешённые бесплатные библиотеки

Версия 1 (октябрь 2026). Читать вместе с `DESIGN_PRINCIPLES.md` и `ADDENDUM_01_REFERENCES_AND_PRESETS.md`. Это список того, что агент может ставить сам. Всё остальное только после согласования с пользователем.

## 1. Правила установки (для любого агента)

1. Ставить только пакеты из этого списка. Новые пакеты не добавлять без разрешения.
2. Версию закреплять точно (без `^` и `~`) и выбирать релиз, которому не меньше двух недель: свежий релиз мог ещё не пройти проверку сообществом.
3. После установки выполнить `npm audit` и показать результат в отчёте.
4. Лицензии: допустимы MIT, Apache-2.0, ISC, BSD. Не ставить GPL/AGPL и любые коммерческие или enterprise-пакеты.
5. Имена настроек и API сверять с установленной версией (`package.json`, документация пакета), а не с памятью агента.
6. Библиотека не должна ломать правила дизайна: цвета только из токенов, никаких чужих тем «по умолчанию».
7. Не заменять рабочие части приложения (график, движок бэктеста) на другие библиотеки ради эксперимента.

## 2. Интерфейс

| Задача | Пакет | Лицензия | Зачем нам |
|---|---|---|---|
| Доступные «безголовые» компоненты (диалоги, меню, выпадающие списки, подсказки, вкладки) | **Base UI** (`@base-ui-components/react`) или **Radix UI** | MIT | Не несут своего вида, полностью стилизуются нашими токенами. Base UI достиг стабильной версии 1.0 в 2026 и стал вариантом по умолчанию в shadcn/ui |
| Раскладка окон: панели, вкладки, плавающие окна, сохранение раскладки | **dockview-react** | MIT | Перетаскивание панелей, плавающие группы, всплывающие окна (удобно для второго монитора), сохранение и загрузка раскладки (пригодится для пресетов рабочих пространств). Версию `dockview-enterprise` не ставить: она коммерческая |
| Иконки | **lucide-react** | ISC | Тонкие линейные иконки, хорошо сочетаются со строгим стилем. Толщину линии задать тонкой (около 1.5) |
| Тосты и уведомления (как «Импульс» на референсе 4) | **sonner** | MIT | Лёгкие, спокойные, легко стилизуются |
| Командная строка действий (быстрый поиск монеты, смена пресета, запуск теста) | **cmdk** | MIT | Подходит терминалу, управление с клавиатуры |
| Длинные таблицы и списки (сделки, лента, стакан) | **@tanstack/react-virtual** | MIT | Рисует только видимые строки, держит плавность на тысячах строк |
| Таблицы с сортировкой и фильтрами | **@tanstack/react-table** | MIT | Без своего вида, наши стили |
| Состояние | **zustand** | MIT | Уже в плане проекта |

**Про shadcn/ui и Tailwind (решение отложено).** Они дают быстрый старт: компоненты копируются в проект и становятся нашими, у Tailwind v4 тема задаётся CSS-переменными. Но их добавление затрагивает существующую стилизацию приложения. Рекомендация по умолчанию: безголовые компоненты (Base UI) плюс наш `tokens.css`, без нового CSS-фреймворка. Tailwind и shadcn ставить только по отдельному решению пользователя, и если ставить, то все цвета сопоставить с нашими токенами, а стиль shadcn по умолчанию (одинаковые скруглённые карточки, тени) не использовать.

## 3. Шрифты и цвет

| Задача | Пакет | Лицензия | Зачем нам |
|---|---|---|---|
| Шрифты интерфейса и чисел | **@fontsource/ibm-plex-sans**, **@fontsource/ibm-plex-mono** | OFL (шрифты) | Локально, без внешнего CDN. Запасной вариант для чисел: JetBrains Mono |
| Работа с цветом (шкалы ликвидаций, проверка контраста в OKLCH) | **culori** | MIT | Ровные цветовые переходы без грязных промежуточных оттенков |
| Шкалы и интерполяция | **d3-scale**, **d3-interpolate** | ISC | Нормировка интенсивности и градиенты для слоя плотностей |

Для самих слоёв плотностей и ликвидаций отдельная графическая библиотека не нужна: они рисуются на canvas через существующие кастомные overlay KLineCharts или на отдельном canvas поверх графика.

## 4. Графики

| Задача | Пакет | Лицензия | Заметки |
|---|---|---|---|
| Основной свечной график | **KLineCharts** (уже в проекте) | Apache-2.0 | Оставляем. Версию брать из `package.json` (сейчас 9.8.12), документацию смотреть именно под неё |
| Малые графики (кривая equity, гистограмма R, спарклайны) | **uPlot** | MIT | Мелкая и быстрая, как известно мне; агент должен проверить лицензию и версию при установке |

**Не добавлять без решения:** вторую свечную библиотеку. Например, TradingView Lightweight Charts (Apache-2.0) требует указывать TradingView как автора на странице для пользователей. Если когда-нибудь её подключать, то это решение пользователя. У неё есть официальный Agent Skill для помощи агентам с актуальным API v5.

## 5. Python и данные (только справочно)

Собственный движок бэктеста остаётся основным. Эти библиотеки можно использовать для сверки и отчётов, но не для замены движка.

| Задача | Пакет | Заметки |
|---|---|---|
| Сверка результатов бэктеста независимым движком | **vectorbt** | Лицензия Apache 2.0 с Commons Clause: бесплатна для использования, но нельзя продавать продукт, основанный на ней. Использовать только как проверочный инструмент |
| Индикаторы | **pandas-ta-classic** | Сопровождаемый форк pandas-ta (на него перешёл vectorbt). Сверять результаты со своими расчётами |
| Данные | **pandas**, **numpy**, **pyarrow** (уже в проекте) | Parquet остаётся хранилищем |

## 6. Что агент проверяет перед установкой каждого пакета

1. Есть ли пакет в этом списке.
2. Совместим ли с React 19 и текущим Vite (peer dependencies).
3. Лицензия.
4. Дата выхода версии: не младше двух недель.
5. Нужен ли пакет для текущей задачи (не ставить «на всякий случай»).
6. После установки: `npm run build`, `npm audit`, отчёт.
