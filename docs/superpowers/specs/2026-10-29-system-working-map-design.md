# Рабочая карта SignalScript — дизайн

## Цель

Создать поддерживаемый навигационный документ, который показывает агенту нужный блок, его контракты, соседние зависимости и сфокусированные проверки без чтения всего репозитория.

## Выбранный подход

Добавить `docs/SYSTEM_WORKING_MAP.md` как оперативный слой между стабильной архитектурой в `ARCHITECTURE.md` и генерируемым каталогом символов в `CODEMAP.md`. В `AGENTS.md` и documentation gate закрепить обязанность поддерживать карту при изменении public interface, потока данных, ownership boundary, контракта или user workflow.

## Границы

Инкремент документирует существующее поведение и удаляет только проверенные runtime-артефакты из предыдущего диагностического коммита. Он не меняет paper execution, риск-лимиты, admission policy, стратегию, БД, API или UI.

## Критерии готовности

- Карта покрывает запуск, selection, paper execution, risk, market-quality, frontend и post-mortem.
- В ней явно разделены историческая оценка и runtime safety vetoes.
- Documentation gate требует карту.
- Runtime snapshots и пустой диагностический файл не остаются в исходниках и не могут случайно добавиться снова.
