# Reproducible Overnight Paper Run

## Scope and invariants

The target is an observable Binance Futures USDT-M **paper-only** diagnostic run for BTCUSDT, ETHUSDT, SOLUSDT, BNBUSDT, XRPUSDT, DOGEUSDT, SUIUSDT, and NEARUSDT. It uses one shared virtual USDT account with an initial equity of $1,000. No code in this effort may submit a real exchange order, change API-key permissions, delete historical data, or represent a diagnostic result as proof of profitability.

The first-run defaults are: 8 hours; 5m entries with closed 15m context; base risk 0.5%; portfolio heat 1.25%; directional heat 0.75%; no more than four positions; x5 exchange-leverage ceiling; no pyramiding; deterministic management remains available when AI is unavailable. Symbols that fail public-market validation are excluded with a recorded reason.

## Explicit limitations

- Historical OHLCV evidence must not be presented as validation of an unavailable historical L2 feed.
- A profile without sufficient OOS evidence can run only when marked experimental and diagnostic.
- The first paper run is operational validation, not evidence of positive expectancy.
- The PVE connection and public-gap backfill are future data work; no credentials, schema changes, or paid APIs are assumed without an explicit deployment configuration.

The primary shared-account entry gate accepts fractions and currently receives hard-coded `0.0125` / `0.0075`; meanwhile M4 accepts percentage values. Consolidate both gates onto named percentage configuration with a conversion boundary and tests, preserving the current 1.25% / 0.75% effective limits.

5. **P0 — browser-smoke:** cold load/layout restoration and the UI/API `account_id` + `run_id` identity require browser verification under clean storage, saved workspace, slow backend and workspace switching. A production build is not browser-smoke evidence.
6. **P0 — full quality gate:** run `scripts/check.ps1`, retain its log and exit code before any paper smoke. Record why platform-skipped tests are skipped and whether an equivalent supported check ran.

**Policy note:** this audit separates units from financial policy. The effective primary limits currently remain 1.25% portfolio heat and 0.75% directional heat. No higher limit is approved by this work. The launcher’s 0.5% per-trade configuration is unchanged. The legacy M4 default was 6% but M4 is off by default; its omitted-config default is now explicitly tightened to the already-effective 1.25% shared gate. M4 no longer repeats the heat calculation: its distinct responsibility is daily DD, kill-switch and downward-only quality sizing; the shared gate remains the sole atomic heat/reservation authority.
