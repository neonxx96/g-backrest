# DECISIONS.md — Архитектурные и технические решения

1. **База данных:** SQLite через `SQLAlchemy` (asyncio + `aiosqlite`) для хранения настроек пользователей, ликвидаций, истории сигналов и рисунков графиков. Это обеспечивает zero-config локально и в Docker.
2. **Ликвидации Binance Futures:** Поскольку у Binance нет исторического REST эндпоинта для ликвидаций, фоновый WebSocket `wss://fstream.binance.com/ws/!forceOrder@arr` сохраняет события принудительной ликвидации в SQLite, и сканер суммирует ликвидации за скользящие 24 часа.
3. **Рыночная капитализация:** CoinGecko public API (`/api/v3/coins/markets`) кэшируется в памяти и SQLite на 1 час для предотвращения превышения rate-limit (30 запросов/мин). Маппинг символов: `BTCUSDT -> bitcoin`, `ETHUSDT -> ethereum` и т.д.
4. **Реконструкция таймфреймов 45m и 6h:** Binance Futures не имеет нативных свечей 45m и 6h. Свечи 45m агрегируются из трех свечей 15m; свечи 6h агрегируются из шести свечей 1h.
5. **CVD (Cumulative Volume Delta):** Рассчитывается на базе свечей через `taker_buy_base_volume`: `taker_buy - (total_volume - taker_buy)` = чистая разница рыночных покупок и продаж.
6. **График на фронтенде:** `klinecharts` v9 с полноценной панелью инструментов рисования (лучи, горизонтальные уровни, фибо, прямоугольники, магнит) и сохранением геометрии по паре/TF в бэкенд.
7. **Telegram Бот:** `aiogram` 3.x в режиме polling на бэкенде с вебхук/polling fallback.
8. **Безопасность секретов:** Все ключи вынесены в `.env`. В коде используются только `os.getenv` через `pydantic-settings` / `python-dotenv`.
